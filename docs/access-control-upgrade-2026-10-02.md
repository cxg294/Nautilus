# 角色与权限系统优化（2026-10-02）

本次完善现有权限系统，不新增账号或调整任何现有角色授权。已应用到本机开发服务。

## 已完成

- 每个认证请求读取当前账号状态、角色和权限。旧 JWT 中的 owner 身份不能绕过降级；禁用、改密码会撤销旧会话，重新启用不会复活旧令牌。
- owner 账号只能由 owner 创建或调整；保护最后一个启用的 owner，禁止修改自己的角色、状态或删除自己。
- `system:user:manage` 管账号，`system:user:approve` 管注册审批。审批员只看到待审批名单；账号管理员不能绕过审批激活或删除待审批账号。
- 系统设置按 `system:settings:edit` 授权，系统运行看板按 `module:analytics-dashboard:access` 授权，支持委派给其他角色。
- 角色列表显示成员人数，可查看成员、修改名称和说明；有成员的角色不能删除，内置角色不能删除。
- 权限变化通过响应中的授权指纹及页面可见时每 30 秒/重新聚焦同步，更新菜单、操作按钮和标签；失去当前页面权限时跳到无权限页。
- 默认开放的工具单独标记，不再显示成可撤销的角色授权。
- 授予管理操作或语音子功能时自动补齐页面入口；取消入口时同时取消相关能力。保存前显示新增、撤销项和受影响成员人数，检测其他管理员造成的过期覆盖。
- 角色、权限、账号和服务设置的管理修改写入审计记录，与修改在同一事务内完成。日志不保存密码、令牌或代理 URL；权限管理页面可查看最近 30 条变更。
- 修复有登录记录的用户被 refresh token 外键引用阻止删除的问题。
- 保护续期和权限同步的并发场景，退出或切换账号后，旧响应不能复活会话。

## 边界

权限同步是请求触发和可见页面轮询，不是 WebSocket 推送；后端在下一次请求立即校验当前权限。公开工具仍沿用 manifest 的开放设置。

本次未涉及工具服务自身的多用户凭据隔离。例如 htcli 仍使用服务器机器的登录状态和缓存；授予课程工具入口不等于解决外部系统的个人授权。

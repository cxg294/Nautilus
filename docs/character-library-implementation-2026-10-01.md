# 人物声音与立绘库实施记录

日期：2026-10-01。范围为人物识别、声音、每张立绘独立的位置与大小；没有人物性格、背景、关系等描写字段。视频和复杂多片段舞台继续暂缓。

## 使用入口与流程

- 「文案创意 → 人物声音与立绘」：新增或选择人物，编辑名称和别名、声音、立绘，再点击「保存」。人物库按 Nautilus 账号隔离，保存到服务端 SQLite。
- 「逐字稿播放器 → 人物库」：将库中的人物添加到项目，或明确替换当前人物配置。「编辑立绘位置与声音」编辑当前项目的快照，也可存为库中新人物或更新原人物库版本。
- 新项目加载库中默认人物；解析新人物时按人物名、显示名和别名识别，未出场的新增人物不加入项目。回到播放器后会刷新库列表；已有项目快照不会因此改变。
- 每张立绘都可拖动、等比缩放、输入百分比、快捷左右/居中、恢复推荐值。可复制同一图片为不同条目、复制某张的位置参数到指定立绘、设置默认立绘。
- 默认立绘用于平静讲解或匹配不到的情况；手动选图优先，其他语气延用已有的表情名称匹配。
- 人物库支持归档/恢复。库更新检查版本冲突；项目与库均可保留自己不同的调整。

## 位置参数盘点

以下参数以当前 16:9 舞台为准。X 是图片底部中心的水平位置，占舞台宽度的百分比；Y 是该锚点的纵向位置，占舞台高度的百分比；高度是**整张原图**的显示高度占舞台高度的百分比，包含透明留白。宽度随原始宽高比计算，不拉伸。

校准先测量 15 张原图的可见范围，再生成舞台对照图检查实际比例。人物可见中心约在左侧 20% 或右侧 80%，宽幅挥手和抬手图单独向内收，确保可见轮廓留在左右 4% 的安全边界内；可见底部约 93%，字幕在底部 8% 附近。禾木的图片底部有少量透明空间，因此原图锚点略下移。艾博士几张表情图顶部留白大，原图高度提高到 90–94%，可见人物仍是适中的半身大小。

## 声音参数盘点

语音继续只走 Nautilus 的语音实验室接口，没有恢复 AI Lib、平台音色 ID 或隐藏兜底旁白。人物库复用实际音色及其 `targetModel`，没有再增加供应商专用的核心人物字段。

2026-10-01 实际列表共 79 个音色；六个预设人物各有 3 个同名音色，均为 `cosyvoice-v3.5-flash`、状态 `OK`，所以不按同名列表首项随机绑定。已有项目中明确保存的本用户声音、模型和语速会作为库初始值；未绑定的角色继续等待用户试听选择。当前账号继承了乌拉乎、禾木、艾博士的已有配置，其他人物可从同名候选中选择。

| 设置 | 当前处理 |
| --- | --- |
| 音色 | 显示名称 + ID 末尾 8 位；展开后显示完整 ID、模型、创建时间、状态 |
| 默认语速 | 新人物建议 1.0×；可调 0.5–2.0×、步进 0.1。已有项目值保留，例如已有艾博士配置为 1.2× |
| 模型 | 新选音色时跟随其目标模型，不凭名称猜模型 |
| 已有试听 | 播放音色保存的样本，明确标注不代表当前语速 |
| 当前语速试听 | 自定义短文本，实际提交当前音色、模型、语速合成后播放 |
| 参考音频 | 内置原始参考样本可播放；也能显式上传新参考音频创建并绑定声音，不后台批量复刻 |
| 音调/音量/人物性格 | 不提供未接入合成服务的假控件；逐句语气仍由台词设置控制 |

使用已有乌拉乎音色完成 1.1× 的实际短句合成，返回音频约 1.745 秒，浏览器 readyState=4、无解码错误。已有试听约 1.84 秒也正常解码。该验证确认合成参数和播放链路可用，不等于全部音色均完成主观听感评审。

## 数据与兼容

- 共用预设：`shared/character-presets.json`；6 人物、15 张独立布局。前后端同源，避免参数漂移。
- 人物库：新模块 `src/views/character-library/`、API `/api/character-library`、迁移 `020_character_library.sql`。每个账号独立记录和版本，归档不删除原文件。
- 图片上传复用已有转码流程：8 MB、限制像素、WebP 转码、用户独立目录。新库图片接口与原工坊图片接口复用物理目录但各自经过权限守卫。
- 人物核心新增可选 `CharacterPose.layout={x,y,height}`。工坊快照保存 `libraryRef={id,revision}`，不与库共享可变对象。
- 项目保存、恢复、JSON 导入导出保留每张布局及库来源。布局改变不会改变音频缓存键；声音/语速变化让受影响台词显示待生成。
- 替换人物快照保留项目内的人物 ID，手选立绘优先按 ID、再按名称映射，缺失时回到自动匹配。
- 新模块沿用原逐字稿角色权限人群；后端继续验证用户身份和模块权限，没有绕过认证。

## 2026-10-02：简化操作与布局

用户反馈配置过于复杂，并明确要求舞台放在中间上方、名称等设置移到右侧、左侧角色列表直接新增。本轮按这个操作顺序调整：

- 左侧为带缩略图的角色列表，「新增角色」就在列表顶部，新建草稿立即显示在列表中。刷新、归档和显示归档角色收进列表更多菜单。
- 中间上方是完整的 16:9 舞台，下方是立绘缩略图和添加立绘。每张图独立拖动、缩放；坐标收进「精细调整」。
- 右侧放人物名称、当前立绘名称、默认立绘按钮、声音、语速和试听。名称与稿件名原来相同时改名同步，已有不同稿件名保留；稿件名和其他叫法在「稿件识别」中。
- 复制立绘、复制位置和移除在「更多」中。试听文本、上传参考音频、原始试听及音色详情在「更多声音设置」中。主界面不展示版本号和完整音色 ID。
- 播放器内共用的角色编辑器同步采用舞台在左、设置在右的布局；窄屏通过 CSS 改为纵向排列。后端接口、持久化方式及既有声音与立绘参数没有迁移。

验证：43 项既有回归测试、全量类型检查、四个修改组件的 lint 和测试构建通过。Chrome 当前 1311×816 首屏完整展示主要操作；新增未保存角色、名称同步、精细调整开合、复制立绘、拖动和缩放已实测。临时角色位置从 80/93 拖到 70.3/82.7；副本高度从 60 调到 50.1，原图仍为 60。临时草稿已丢弃，已有库记录未改写。声音按钮以现有乌拉乎音色、1.0× 合成短句，音频 1.92 秒、readyState=4、无解码错误。播放器弹窗可正常打开、无横向溢出，原三句稿仍为 3/3 就绪。
